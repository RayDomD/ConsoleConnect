# Hosted workspace setup

Console Connect can use a team-owned Supabase project instead of a computer host. The desktop needs only the project URL and its publishable key. Keep the service or secret key and GitHub token on the Supabase function, never in the desktop app or this repository.

1. Create a Supabase project and enable anonymous sign-ins under Authentication. Existing teammates can keep their anonymous identity until they connect an account. To retain their workspace membership, enable **Allow manual linking** before they use GitHub or Google sign-in. Clearing app data before linking loses the anonymous identity and requires a new invitation.
2. Apply `migrations/20260923120000_console_connect.sql` and `migrations/20260923130000_github_bound_invites.sql` with the Supabase CLI migration workflow. They create the workspace tables, account-bound invitations, member-only revision feed, server-only write functions, and their row-level security rules.
3. Configure `GITHUB_TOKEN` as an Edge Function secret with read access to the workspace's repositories. The function reads a proposed decision file at its exact commit and checks pull-request review and merge status through GitHub. To let owners optionally send GitHub collaborator invitations, configure a separate `GITHUB_INVITE_TOKEN` with Administration write access limited to the repository. A private personal repository grants collaborators write access, so the app offers this only for contributors. The GitHub invitation must be accepted separately. The Supabase URL and server-side secret key are supplied by the Edge Function environment.
4. For GitHub sign-in, create a GitHub OAuth app and enable the GitHub provider in Supabase with its client ID and secret. For Google sign-in, create a Google OAuth web client and enable the Google provider the same way. Both providers use `https://<project-ref>.supabase.co/auth/v1/callback` as their provider callback. Add `http://127.0.0.1:24681/auth/callback` to Supabase Authentication → URL Configuration → Redirect URLs. Keep both client secrets in the provider settings, never in the desktop app or repository. The desktop uses a browser sign-in and a local PKCE callback; it requests no GitHub repository scopes.
5. Run `npm run build:hosted`, then deploy the `console-connect` Edge Function. Leave JWT verification enabled. The desktop's “Host with Supabase” and “Join with Supabase” forms use the project URL and publishable key. Owners can share one-time invitation links containing these public connection details and the invitation code. Teammates paste the link into Console Connect, sign in with GitHub or Google if they wish, and join. Signed-in members can restore their hosted project list on another computer once it has the same Supabase URL and publishable key.

`npm run check:hosted-schema` applies the migration to a disposable local PostgreSQL database and checks invitation consumption, revision compare-and-swap, and member visibility. The domain tests check assignment approval, retry IDs, private drafts, review separation, and merge completion. On 2026-09-23, the migration and Edge Function were deployed to the Console Connect Supabase project; anonymous sign-in and a rejected nonmember request passed live. Realtime delivery, GitHub verification, and a two-computer run still need validation. Hosted view-only console sharing uses Realtime broadcast on private `console-terminal:<workspace>:<task>` topics; `migrations/20260925130000_console_terminal_sharing.sql` lets members listen and only the task's assignee send. Presence for the Office uses `migrations/20260925120000_console_presence.sql`. Both migrations and the updated Edge Function must be deployed before hosted sharing and presence work; the schema check covers them locally, but they have not been run against the live project. Local tool execution remains on each member's computer.
