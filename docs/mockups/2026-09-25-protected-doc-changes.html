Q13 · Follow-up: what happens when someone changes a doc

Casey, a Contributor, edits an ADR. What happens?

First, a correction

Q11 made orchestration open to everyone. The permission is who can assign, not who can orchestrate. Changing docs is a separate thing again: docs are files in Git, so the rules for changing them are the repository's rules, not Console Connect's.

The short answer

Casey's edit stays on her task branch. The reviewer is told plainly that it changes an ADR, and nobody's brief sees it until it's merged to main on GitHub, under GitHub's own branch protection. The spec already says Console Connect never bypasses repository permissions.

What B adds to the project map new, part of B

Mark docs as protected

The map can tag entries protected, for example the spec, ADRs, DESIGN.md, and decisions.

Flag it in review

A package that touches a protected doc shows a warning, and only an Owner or Reviewer can accept it, which Q11's roles already enforce.

Official decisions can't drift

The host keeps the approved text. If docs/decisions/*.md changes outside the app, the brief shows "differs from the approved decision" and uses the approved one.

Direct pushes are visible

If the repo allows pushing straight to main, Console Connect can't stop it (GitHub decides), but the brief flags "changed on main outside a package".
