Q15 · Learning curve

Yes, there's a learning curve, but it lands on one person, and the app can carry most of it

Most of the team never sees the path as something to learn. Workers still get a task, approve it, and submit. The person orchestrating is the one who meets new ideas: stages, playbooks, and skipping. The question is how to make that first week easy.

Who has to learn what

S
WorkersSam, Casey
  • Nothing new: tasks arrive as before
  • They see a "Spec" link in the brief, which their AI reads for them
R
ReviewersRiley
  • Same Accept and Request changes as before
  • New: approving a spec (it's a decision, so a familiar flow)
B
Whoever orchestratesBlair
  • Idea cards, five stage names, when to skip
  • But the orchestrator AI runs every playbook, so Blair picks and the AI does the work

How should an idea pick its stages?

APick a size, and the path followsRecommended

One choice when you create the idea. The size sets which stages apply, so nobody has to know the whole system. There's always one "Next step" button.

New idea
Quick fixA bug or small change. Straight to a task.
FeatureA few tasks. Grill, then tickets.
Big ideaMany sessions. Full path with a spec.

You can change the size later. Skipping a stage inside a size asks for one line of why.

Good
  • One decision, in plain words
  • Quick fixes never feel slowed down
  • "Next step" means nobody memorizes the order
Trade-off
  • Someone might pick the wrong size (it's changeable)
BEvery idea shows all five stages

The same card for everything. People skip stages one by one, each with a reason.

Ideas

grill · skipped: "typo"spec · skipped: "typo"tickets · skippedbuildreview
Session timeout feels too long
grillspecticketsbuildreview

A typo fix needs three skip reasons.

Good
  • Fully consistent
Trade-off
  • Small work feels bureaucratic
  • Everyone has to learn all five stages up front
Plain words in the UI

Stages show as "Talk it through", "Write it up", "Split into tasks", "Build", "Review". "Grill" and "tickets" stay in the playbook command names only.

A worked example on day one

New workspaces get one sample idea, already walked through with its files, to open and read. You can delete it anytime.

The AI explains itself

Each playbook starts by saying in one line what this stage is for and what it will produce.

Nothing is required

Plain tasks still work without ideas. The path is a guide you grow into, not a gate (Q14 B).
